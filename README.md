# 🤖 BotMAX — добавь своего бота в **MAX**

Запусти своего **OpenClaw** / **Hermes** / любого **telegram-бота** в мессенджере
**MAX** (бывший VK Messenger) **одной командой**:

```bash
curl -fsSL https://raw.githubusercontent.com/DemoMY/BotMAX/main/install.sh | bash
```

BotMAX — крошечный дамон **без внешних зависимостей**, который реализует
**Telegram Bot API** поверх официального **MAX Bot API**. Твой агент по-прежнему
говорит по-телеграфски — BotMAX сам переводит всё (текст, медиа, инлайн-клавиатуры,
колбэки, меню команд) в MAX.

```
┌──────────────────┐   Telegram Bot API   ┌─────────────────────┐   MAX Bot API    ┌──────────────────┐
│  OpenClaw /  │◄──────────────────►│  BotMAX daemon   │◄──────────────────►│  MAX messenger  │
│  Hermes / grammY│   http://127.0.0.1:18790   │  (этот репозиторий)  │   platform-api2   │  (твой телефон) │
└──────────────────┘                    └─────────────────────┘          └──────────────────┘
```

---

## ✨ Возможности

- **Установка в одну команду** — скачивает, спрашивает MAX-токен, проверяет его
  живьём, поднимает per-user `systemd`-сервис и **автоматически настраивает
  OpenClaw**, если он найден.
- **Ноль npm-зависимостей** — только встроенные модули Node.js ≥ 18.
- **Настоящий MAX Bot API** (официальный, документирован на dev.max.ru): текст,
  медиа (фото / видео / аудио / файлы), **инлайн-клавиатуры**, **кнопки-колбэки**,
  **меню команд** (`setMyCommands`), редактирование и удаление сообщений.
- **Только loopback по умолчанию** (`127.0.0.1`) — токен не покидает машину.
- **Не нужен системный TLS-траст** — сертификат корневого УЦ Минцифры прилагается
  и используется только самим дамоном через `NODE_EXTRA_CA_CERTS`.
- **Прод-уровень из коробки**: `/healthz`, корректное завершение, атомарное
  сохранение состояния, 18 интеграционных тестов.

## 🚀 Быстрый старт (OpenClaw)

```bash
curl -fsSL https://raw.githubusercontent.com/DemoMY/BotMAX/main/install.sh | bash
```

Установщик:

1. скачает BotMAX в `~/.local/share/botmax/`,
2. спросит **MAX-токен бота** (взять: [business.max.ru/self](https://business.max.ru/self)
   → Чат-боты → Настройки, или у бота **«MAX для бизнеса»** командой **Получить токен**),
3. запустит `botmax.service` на `127.0.0.1:18790` и **проверит токен** через
   настоящий `GET /me`,
4. если найдёт `~/.openclaw/openclaw.json`: **сделает бэкап**, пропишет
   `channels.telegram` (`apiRoot=http://127.0.0.1:18790`, `botToken=9:botmax`)
   и перезапустит `openclaw-gateway.service`,
5. напечатает чек-лист проверки.

> У тебя в OpenClaw уже настроен настоящий телеграм-бот? Установщик **не
> перезапишет** его. Чтобы перенаправить OpenClaw на BotMAX, перезапусти
> установку с `BOTMAX_FORCE=1`.

**Проверка в приложении MAX:**
1. открой своего бота, отправь любое сообщение — агент отвечает;
2. введи `/commands` — пришлётся список команд с инлайн-кнопками;
3. нажми кнопку — сообщение отредактируется на месте.

## 🧩 Ручная настройка / Hermes / любой Bot API-клиент

Hermes и другие агенты используют собственный мессенджер-стек — BotMAX
является *просто Telegram Bot API сервером*, поэтому его можно подключить везде,
где можно переопределить endpoint Bot API:

```bash
# 1) установить без авто-настройки OpenClaw (пропустит шаг с агентом):
#    просто запусти установщик — если ~/.openclaw нет, он это пропустит.

# 2) запуск вручную (без systemd — Docker, контейнеры, macOS, Windows):
npm i -g .  # или: node bridge.js
BOTMAX_BOT_TOKEN=твой_токен node bridge.js

# 3) укажи агенту:
#    apiRoot  = http://127.0.0.1:18790
#    botToken = 9:botmax   (любая непустая строка, которую примет бот)
```

Для агентов на `grammY` это drop-in `apiRoot`. Для OpenClaw то же самое вручную —
поле `channels.telegram` в `~/.openclaw/openclaw.json`:

```jsonc
{
  "channels": {
    "telegram": {
      "enabled": true,
      "apiRoot": "http://127.0.0.1:18790",
      "botToken": "9:botmax",
      "dmPolicy": "allowlist"
    }
  }
}
```

## 🔧 Конфигурация

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `BOTMAX_BOT_TOKEN` | — | MAX-токен бота (обязателен) |
| `BOTMAX_HOST` | `127.0.0.1` | адрес прослушивания (только loopback — меняй с осторожностью) |
| `BOTMAX_PORT` | `18790` | порт Telegram-Bot-API |
| `BOTMAX_UPSTREAM` | `https://platform-api2.max.ru` | базовый URL MAX API |
| `BOTMAX_STATE` | `~/.config/botmax/state.json` | хранение маркера long-poll |
| `BOTMAX_INSECURE` | выкл | разрешить http-апстрим (только для тестов — не для прода) |
| `NODE_EXTRA_CA_CERTS` | задаёт установщик | путь к `certs/russian-trusted-root-ca.pem` |

Флаги/переменные `install.sh`: `BOTMAX_BOT_TOKEN` (не-интерактивный режим),
`BOTMAX_PORT`, `BOTMAX_FORCE=1`, `BOTMAX_INSTALL_DIR`.

## 🔒 Модель безопасности

- слушает только `127.0.0.1` — мост это **локальный** сервис для твоего агента;
- MAX-токен хранится в `~/.config/botmax/env` (`chmod 600`);
- TLS к MAX — с приложенным **корневым УЦ Минцифры России**
  (SHA-256 `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`,
  взят с gu-st.ru). Ставить сертификат в систему не нужно;
- скачивание медиа по не-HTTPS-URL по умолчанию запрещено.

*MAX — товарный знак владельца. Проект неофициальный и не аффилирован с ним.*
